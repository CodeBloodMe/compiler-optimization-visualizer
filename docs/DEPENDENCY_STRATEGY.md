# Aegis Dependency & Reference Strategy

This document details the architectural foundation, dependency strategy, API integration, and license compliance for the **Aegis** security-first compiler project, referencing its core technical foundations:

1. [bytecodealliance/wasmtime](https://github.com/bytecodealliance/wasmtime)
2. [bytecodealliance/wasm-tools](https://github.com/bytecodealliance/wasm-tools)
3. [lalrpop/lalrpop](https://github.com/lalrpop/lalrpop)
4. [rust-hosted-langs/book](https://github.com/rust-hosted-langs/book)

---

## 1. Architectural Principles

### Modularity Over Monolithic Inlining
Rather than cloning external codebases or embedding entire multi-megabyte repositories into the project tree, Aegis relies on **official, published, and version-locked Rust crates** via Cargo. This architecture ensures:
- **Reproducible Builds:** Exact lockfile tracking (`Cargo.lock`).
- **Clear Intellectual Property Separation:** First-class Aegis components (frontend, AST, custom IR, taint analysis, optimizer, visualizer) remain distinctly original and cleanly decoupled from foundational execution substrates.
- **Maintainability & Security:** Critical WebAssembly runtime execution boundaries receive upstream security patches directly through dependency updates.

## 2. Technical Reference & Integration Analysis

### A. Wasmtime (`bytecodealliance/wasmtime`)
- **Repository:** `https://github.com/bytecodealliance/wasmtime`
- **License:** Apache License 2.0 with LLVM Exception
- **Crate Version:** `wasmtime = "49.0"`
- **Role in Aegis:** High-performance, sandboxed WebAssembly execution engine with fine-grained host limits.
- **Integrated Capabilities & APIs:**
  - `wasmtime::Config::consume_fuel(true)`: Enables deterministic instruction fuel metering.
  - `wasmtime::Store::set_fuel(budget)`: Sets the module's initial fuel budget.
  - `wasmtime::Store::get_fuel()`: Computes precise fuel consumption metrics for execution profiling.
  - Fuel Trap Trapping: Catches fuel exhaustion traps and classifies them as deterministic `FuelExhausted` events.
  - `wasmtime::Linker::func_wrap("aegis_host", ...)`: Exposes isolated host capability functions (e.g. `print_i32`, `read_i32`, `sanitize_i32`) only when authorized by runtime policy.
  - `wasmtime::Module::imports(&module)`: Inspects import tables prior to invocation, rejecting unknown imports and enforcing capability policies.

### B. wasm-tools (`bytecodealliance/wasm-tools`)
- **Repository:** `https://github.com/bytecodealliance/wasm-tools`
- **License:** Apache License 2.0 with LLVM Exception
- **Crates Used:**
  - `wasm-encoder = "0.261"`: Low-level binary emitter for generating valid WebAssembly sections (Type, Function, Import, Memory, Export, Code).
  - `wasmparser = "0.261"`: Zero-allocation validator validating structural invariants and operand typing of generated bytecode (`wasmparser::validate`).
  - `wasmprinter = "0.261"`: Converts binary `.wasm` into WebAssembly Text Format (`.wat`) for inspection (`aegis inspect --wat`).
- **Integration Boundary:**
  - Aegis does not duplicate the internal binary encoding or parser logic. The custom IR (`src/ir.rs`) lowers directly to `wasm-encoder` instructions, and `wasmparser` ensures strict bytecode correctness before writing to disk.

### C. LALRPOP (`lalrpop/lalrpop`)
- **Repository:** `https://github.com/lalrpop/lalrpop`
- **License:** Apache 2.0 / MIT
- **Evaluation for AegisLang:**
  - **Formal Specification:** Aegis provides a complete, formal LR(1) grammar definition in [`src/aegis.lalrpop`](../src/aegis.lalrpop). This serves as the reference grammar for the language.
  - **Parser Trade-off Analysis:**
    - *LALRPOP Advantages:* Formally verified shift/reduce conflict detection, automated precedence resolution, concise declarative syntax.
    - *Handwritten Recursive-Descent / Pratt Parser ([`src/parser.rs`](../src/parser.rs)):* Provides zero-build-script compilation speed, exact line/column [`Span`](../src/source.rs) tracking without token wrapper glue, fine-grained diagnostic error recovery, and zero external build-time dependencies.
  - **Decision:** Aegis maintains [`src/aegis.lalrpop`](../src/aegis.lalrpop) as the formal language grammar specification, while utilizing the optimized handwritten recursive-descent parser in [`src/parser.rs`](../src/parser.rs) for production compilation and CLI diagnostic reporting.

### D. Rust Hosted Languages Guide (`rust-hosted-langs/book`)
- **Repository:** `https://github.com/rust-hosted-langs/book`
- **License:** Creative Commons CC0 / Open Documentation
- **Patterns Adopted in Aegis:**
  - **Scoped Symbol Resolution:** Multi-tier lexical environment stack (`Scope` in [`src/semantics.rs`](../src/semantics.rs)) for tracking variable mutability and types.
  - **Custom Typed IR:** Separation of frontend AST ([`src/ast.rs`](../src/ast.rs)) from execution-neutral Intermediate Representation ([`src/ir.rs`](../src/ir.rs)).
  - **Basic Block Control-Flow Lowering:** Flattens structured `if/else` and `while` constructs into linear instruction sequences with jump labels and conditional branch terminators.
  - **Pipeline Isolation:** Decoupled stages (Lexing $\to$ Parsing $\to$ Semantics $\to$ IR Lowering $\to$ IR Verification $\to$ Optimization $\to$ Codegen).

## 3. First-Class Aegis Components (Original Contributions)

The following components form the core original intellectual contribution of Aegis:

1. **AegisLang Language Specification:**
   - Explicit capability contracts (`requires console.write;`).
   - Immutable-by-default typed variables (`let` vs `let mut`).
   - Formal grammar specification ([`src/aegis.lalrpop`](../src/aegis.lalrpop)).

2. **Custom Typed Intermediate Representation & Verifier ([`src/ir.rs`](../src/ir.rs)):**
   - Independent basic-block based IR supporting local slots, typed operands, and explicit control-flow branches.
   - Built-in static verifier checking operand typing, local indexing, and terminator validity.

3. **Static Taint Analysis Engine ([`src/security.rs`](../src/security.rs)):**
   - Inter-procedural and intra-block taint tracking from untrusted sources (`read_i32`) to privileged sinks (`print_i32`).
   - Certified sanitization barriers (`sanitize_i32`).
   - Causal trace path reconstruction and diagnostic reporting.

4. **Capability-Based Access Control Architecture:**
   - Two-phase authorization model separating compile-time declarations from runtime TOML policy grants.
   - Pre-invocation inspection of WebAssembly import tables.

5. **Security-Aware Optimization Passes ([`src/optimizer.rs`](../src/optimizer.rs)):**
   - Constant folding, algebraic identities, and dead block elimination operating directly on the custom IR.
   - Preserves all side-effecting capability calls and security invariants.
   - Differential execution verification demonstrating up to 44.4% fuel reduction.

6. **Reproducible Benchmarking Framework & Visualizer:**
   - Automated latency, memory, fuel, and security detection evaluation ([`benchmarks/run_benchmarks.py`](../benchmarks/run_benchmarks.py)).
   - Interactive visualizer UI ([`visualizer/`](../visualizer/)) for pipeline inspection, policy adjustment, and live execution.
